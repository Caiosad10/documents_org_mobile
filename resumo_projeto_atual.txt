RESUMO DO PROJETO: ORGANIZADOR DE DOCUMENTOS MOBILE

1. OBJETIVO

O objetivo e recriar um projeto Python existente chamado documents-org, originalmente feito em um unico arquivo app.py com Streamlit, Supabase e toda a logica misturada: interface, banco, autenticacao, upload, regras de negocio e estilos.

A intencao e transformar essa ideia em um app mais organizado, mobile-first, futuramente usavel no celular, mantendo Python como linguagem principal, porque o usuario conhece apenas Python.

O app original e um organizador financeiro/de documentos. Ele permite:

- login/cadastro;
- visualizacao anual por meses;
- calendario mensal;
- tela de documentos por dia;
- upload de arquivos PDF/imagem;
- classificacao por tipo de documento;
- vinculo entre comprovantes e outros documentos;
- calculo de pendencias;
- exclusao segura de documentos e vinculos.

3. STACK ATUAL

A stack comecou como Kivy/KivyMD, mas foi trocada para Flet.

Motivo da troca:

- Kivy apresentou problemas de instalacao no Windows com Python 3.14.
- Flet foi escolhido por manter Python, ser mais simples de instalar e ainda permitir app desktop/mobile/web.
- O projeto usa Flet 0.85.1 instalado na venv do usuario.

8. ERROS CORRIGIDOS

8.1. Kivy nao instalava

Erro:

No matching distribution found for kivy_deps.sdl2_dev

Causa:

- venv criada com Python 3.14;
- Kivy no Windows depende de wheels nativas;
- nao havia dependencias compativeis.

Decisao:

- abandonar Kivy/KivyMD;
- migrar para Flet.


8.2. pyiceberg falhando

Erro:

error: Microsoft Visual C++ 14.0 or greater is required
Failed building wheel for pyiceberg

Causa:

- dependencia indireta do SDK de Storage/Supabase;
- tentativa de build C++ no Windows.

Decisao:

- remover SDKs gotrue, postgrest, storage3;
- implementar Supabase via HTTP direto com httpx.


8.3. FilePicker on_result

Erro:

TypeError: FilePicker.__init__() got an unexpected keyword argument 'on_result'

Causa:

- API do Flet 0.85.1 mudou;
- FilePicker.pick_files() e assincrono e retorna arquivos.

Correcao:

- remover on_result;
- criar metodo async pick_file;
- usar files = await self.file_picker.pick_files(...).


8.4. ft.padding.symmetric

Erro:

AttributeError: module 'flet.controls.padding' has no attribute 'symmetric'

Causa:

- API nova do Flet nao possui esse helper.

Correcao:

- criar helper proprio pad(horizontal, vertical).


8.5. ft.border.all

Problema semelhante ao padding.

Correcao:

- criar helper proprio border_all(width, color).


8.6. ft.app() deprecated

Aviso:

DeprecationWarning: app() is deprecated since version 0.80.0. Use run() instead.

Correcao:

- trocar ft.app(target=main) por ft.run(main).


8.7. ElevatedButton deprecated

Aviso:

ElevatedButton is deprecated since version 0.80.0

Correcao:

- trocar por ft.Button.


8.8. FilePicker renderizado como controle desconhecido

Erro visual:

Unknown control: FilePicker

Causa:

- FilePicker foi colocado em page.overlay;
- em Flet 0.85.1, ele e Service, nao controle visual.

Correcao:

self.page.services.append(self.file_picker)


8.9. GridView shrink_wrap

Erro ao abrir calendario:

GridView.__init__() got an unexpected keyword argument 'shrink_wrap'

Causa:

- GridView do Flet 0.85.1 nao aceita shrink_wrap.

Correcao:

- remover shrink_wrap=True.

10. ESTADO ATUAL

O app ja abre, permite login, selecao de mes e navegacao inicial. Foram corrigidos os erros visuais e de API conhecidos ate o momento.

O estado atual parece promissor, mas ainda esta em fase de estabilizacao porque Flet 0.85.1 tem mudancas recentes de API, e varias partes precisaram ser ajustadas conforme os erros apareciam.

O projeto esta num caminho mais leve do que Kivy, porque:

- instalacao ficou simples;
- dependencias nativas foram evitadas;
- Python 3.14 nao esta mais bloqueando a instalacao;
- Supabase foi desacoplado dos SDKs problematicos.


11. PONTOS QUE AINDA PRECISAM SER AVALIADOS

1. Se Flet e realmente o caminho final para mobile ou apenas um bom prototipo desktop/mobile-ready.
2. Se vale manter Supabase via HTTP manual ou voltar para SDK futuramente em Python mais estavel.
3. Se o design atual em Flet esta bom o suficiente ou precisa ser redesenhado com mais cuidado.
4. Se o app deve continuar online-first ou ganhar modo offline com SQLite.
5. Se o upload via FilePicker sera suficiente no Android ou precisara adaptacao especifica.
6. Se a navegacao deve continuar em um unico main.py ou ser quebrada em modulos depois que estabilizar.
7. Se a seguranca/RLS do Supabase esta compativel com as chamadas HTTP atuais.
8. Se o build Android com flet build apk sera viavel no ambiente do usuario.
